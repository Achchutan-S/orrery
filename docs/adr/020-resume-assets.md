# ADR-020 — Resume: one content source, generated assets served as release-controlled routes

Status: accepted (1 November 2026) · Implements blueprint task 15 (resume part). Reference: [resume.md](../resume.md).

**Decision.**

1. **Content lives once**, in `apps/site/src/experiences/resume/content.ts`. The page renders it; the PDF is that page printed; the link-preview image is a card built from it.
2. **The PDF and image are generated by Playwright's Chromium** (`pnpm --filter @pu/site resume:assets`), not by a PDF library: Playwright is already a dev dependency, the PDF is the page's own print stylesheet (one design, not two), and nothing is fetched from the network. They are committed; a content hash (`source.sha256`) and a text-extraction test fail when they fall behind `content.ts`. Generation is not part of `astro build`, which would need a browser on every build (including Vercel's).
3. **The files are routes, not `public/` files.** `public/` ships to every build, so a draft resume's PDF would be in production. As endpoints of the `resume` experience (`/resume/resume.pdf`, `/resume/og.png`) they are built only where the experience is mounted, and the leak scan treats them like its pages. `routes.ts` learned that a route ending in a file extension produces that file (not `.html`), and the smoke test expects such routes to answer with their own content type.
4. **`ExperienceRoot` takes an optional `image`**, passed to `SeoHead`; no new metadata code.
5. **A `profile` section** joins the catalog's optional `section` values, for pages about the owner rather than the work.

**Consequences.** Publishing the resume is one release-state edit; its files go with it. Regeneration is manual (documented, and enforced by tests). A style change without a content change is not detected by the hash.
