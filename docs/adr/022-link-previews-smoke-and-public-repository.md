# ADR-022 — Link-preview images from the catalog, environment-aware smoke tests, and what a public repository exposes

Status: accepted (3 November 2026) · Engineering audit Phase C (F08, F17, F04). Supersedes [ADR-014](014-repository-checks.md) known limit 1 ("og:image is not enforced") and resolves tracker decision 4.

## Context

- The catalog had an `ogImage` field ("path relative to the experience folder") that nothing read. The resume passed its image to `ExperienceRoot` separately, so the image was declared twice in spirit and once in code, and every other page had no `og:image`. `check:metadata` did not require one.
- The smoke test checked `text/html` for pages but not the media type of files, hashed assets or `public/` files, so an asset answered by an HTML fallback passed. A local `astro preview` run failed every Vercel-only check (headers, redirects, caching), with no way to tell those apart from real failures. A network error crashed the run with a stack trace.
- The repository is public (tracker decision 5). The release gate decides what the **website** builds; it has never controlled what GitHub serves. Some documentation said the draft resume was "not publicly accessible" without that distinction.

## Decision

1. **`ogImage` is the pattern of one of the experience's own `.png`/`.jpg` routes** (for the resume, `/resume/og.png`). `validateCatalog` enforces it (`og-image-route`), so an image is built only where its experience is mounted (ADR-020): a draft's catalog entry can name an image without publishing it. `ExperienceRoot` passes the catalog value to `SeoHead`; there is no page-level override, because no page needs one.
2. **The platform has one default card**, `apps/site/public/og.png` (1200×630, platform font and colours, names only the site), used by every page whose experience sets no `ogImage`, including the Index, the Journal, the samples and the 404 page. It is generated by `pnpm --filter @pu/site og:platform` and listed in `PLATFORM_FILES`. Per-entry images for writing remain Phase 2 (blueprint 3.10); an experience can add one now through `ogImage`.
3. **Every page states its image absolutely**: `og:image` is `new URL(image, site)` (the production origin, `VERCEL_PROJECT_PRODUCTION_URL`, also in previews), with `og:image:width`/`height` and `twitter:card` `summary_large_image`.
4. **`check:metadata` validates the built HTML**, not the catalog: every page needs `og:type`, `og:title`, `og:description` and an `og:image` that is an absolute URL on the site's origin naming a PNG or JPEG present in the build, plus the large-image Twitter card. Listed pages need a canonical URL equal to `og:url` and to the page's own address.
5. **The smoke test checks what it gets, not only that it got something**: media types by extension for pages, file routes, `_astro` assets and `public/` files (charset parameters allowed); the `vercel.json` headers on every page and 404 response, not only `/`; revalidating `Cache-Control` for stable addresses and immutable for hashed assets; every `og:image` a page names answers 200 as an image. A network error is retried once, then reported with its path and cause.
6. **`--local` is explicit and narrow**: against `astro preview` on localhost, `pnpm smoke <url> --env <env> --local` skips exactly the Vercel-only checks (`vercel.json` headers, clean-URL and trailing-slash redirects, `Cache-Control`) and prints that it did. It refuses any host other than localhost, so a deployment is always checked in full. Everything else (release-driven 200/404, content types, flags, canary, platform files, link-preview images) runs in both modes.
7. **Four separate things decide who can see a file**, and documentation must not blur them:

   | Layer | Decided by | A draft experience |
   | --- | --- | --- |
   | The website | `config/release.json` per environment, enforced at build time | absent from production; built in previews |
   | The repository | GitHub repository visibility (public today) | its source, content and committed files (the resume's PDF and image included) are readable on GitHub, including raw file URLs |
   | Git history | every pushed commit | earlier versions stay readable even after a file changes; nothing has been rewritten |
   | The Control Center | the owner's machine | shows every experience; it is local and never deployed |

   A draft, owner-only or unlisted release keeps an experience off the website. It does not make its files private. Making the repository private or rewriting history is the owner's decision (tracker decisions 5 and 6).

## Consequences

- Link previews work on every public page once deployed; an experience opts into its own image with one catalog line, and the image follows the experience's release state.
- A smoke run against a local build is a meaningful pass/fail, and a run against Vercel is never weakened by it. The production deployment of `9b5fe81` passed every new check on 3 November 2026 except `/og.png`, which does not exist until this change is deployed.
- `public/og.png` ships in every build; it names only the site.

## Not done

- No per-entry generation of link-preview images (Phase 2).
- No validation of image dimensions in `check:metadata` (the platform card and the resume's card are both generated at 1200×630).
- Hosted preview smoke not yet run on these changes (needs a push; [deploy runbook](../runbooks/deploy.md#deployment-procedure)).
