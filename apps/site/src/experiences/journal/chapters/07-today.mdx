## Available now

<Claim standing="verified">

Every production build of this repository contains [the Index](/) at the front page and every experience listed below. This list is not written by hand: it is generated from the catalog and the release file each time the site is built, so it cannot fall out of date. The live site shows this version once it is deployed; until then it shows the earlier, plainer index.

</Claim>

<Inventory />

<Claim standing="verified">

The front page is the Index: a broadsheet that sets each experience's headline in a face echoing its own typography and files it under a section. On every page a small mark in the corner, the Beacon, leads back to it and opens a list of every public destination with ⌘K or Ctrl K. Both are built from the same public list as everything else, so nothing unreleased can appear in them. The Beacon's script is about one kilobyte; pages that had no JavaScript still have none of their own.

</Claim>

<Claim standing="verified">

Underneath them: the release model, the catalog, release-driven routing, the shared page shell and accessibility tokens, the Content Security Policy, the four repository checks, the browser suite, continuous integration, and the deployment configuration.

</Claim>

## Built, but only in some environments

<Claim standing="verified">

Draft experiences, including the hostile stylesheet and the leak canary, are built in local development and in previews, and never in production. The explorer's inspector panel appears only in previews. All of this follows from one file, `config/release.json`.

</Claim>

<Claim standing="verified">

The resume is one of those drafts. Its content was drawn from the owner's own resume and checked against the project repositories it cites. Its page, a two-page PDF and a link-preview image are generated from a single source file, and the PDF and image are served by the resume's own routes, so they exist only where the page does. It has been implemented and verified locally: its text is searchable in the PDF, the page ships no script but the Beacon, and production builds contain none of it. It has not been deployed and is not publicly accessible; it becomes public when the owner approves its content and changes its release entry.

</Claim>

## Not built yet

<Claim standing="planned">

- Owner sign-in, audiences, invitations and a full authorization system.
- A publishing interface; today, publishing is an edit to the release file and a commit.
- Private experiences and the private content store.
- An audit history beyond Git, and usage analytics or dashboards.
- The writing collection, search and feeds.
- A custom domain.

</Claim>

## Where the build differs from the blueprint

<Claim standing="implemented">

Each difference is recorded in an architecture decision record:

- **Astro 7 instead of Astro 6** (ADR-011), because Astro 7 had been released and kept every routing guarantee.
- **The Beacon's palette is a small plain script**, not a React island, because React alone is four times the budget the blueprint sets for the Beacon (ADR-019).
- **A small custom import checker** instead of ESLint with dependency-cruiser, because two of the rules need knowledge of the repository a linter cannot express (ADR-014).
- **Browser tests run against local builds**, not against Vercel previews, so continuous integration needs no Vercel credentials; the live smoke test covers what only Vercel does (ADR-015, ADR-016).
- **Link-preview images are not required yet**, although the foundation checklist asks for them; no page has one (ADR-014).
- **The repository is public**, where the blueprint planned a private one (ADR-003).

</Claim>
